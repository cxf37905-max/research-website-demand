# 网站用户与需求研究方法

## 研究与写作分离

研究阶段先按 `evidence-standard.md` 收集、去重和交叉核验大量用户原话，再
分别完成用户理解、逐产品理解和机会理解。不得边采集边把身份字段、官网功能、
评价摘录、计数或等级拼成外部报告；内部研究账本用于发现缺口和推动下一轮
研究，不是报告草稿。用户、产品和机会理解都使用三态：`理解充分`、
`证据受限`、`继续研究`。重要方向尚未饱和且仍有公开线索可追时标为
`继续研究`；达到公开范围饱和或相应失败处理终止条件后，
再根据完成门槛标为 `理解充分` 或 `证据受限`。只有理解充分时才创作完整
用户故事、完整逐产品理解或完整机会判断；证据受限时只写与现有证据相称的
回答、未知和反证，不用叙事补齐。

内部研究阶段继续使用编号、门槛、计数、等级和档案字段完成追踪与审计，
但外部写作不得显示这些内部标记。外部固定按“完整证据总清单 → 全部不同用户
群体的沉浸故事 → 固定 14 问”输出；来源统一使用 `evidence-standard.md` 规定的
直接链接、完整调研总结、研究观点/局限和产品营销文案格式。外部不展示用户
逐字原话，不在本方法中另造证据格式。

### 无浏览器研究边界

整个研究过程禁止打开或控制可见浏览器、无头浏览器、Chrome、应用内浏览器、
计算机界面或任何浏览器自动化。不得调用需要模拟点击、滚动、展开、切换排序或
页面交互的浏览器能力。只使用搜索引擎、普通网页读取、直接 HTTP、公开 API、
公开 RSS/JSON/结构化数据、站点地图及其他不启动浏览器进程的公开访问方式。

这条边界优先于覆盖数量，但不对整页一刀切：如果动态评论、折叠回复或公开排序
无法完整取得，先判断是否已经完整取得一篇主帖或某条独立评论及其必要上下文。
满足时作为范围有限证据，只支撑该用户的具体经历；只有摘要、截断内容、第三方
转述或缺少必要上下文时，才作为受限线索。不得为了扩大证据范围而打开浏览器。

## 1. 建立产品线索图

先查看首页、功能、使用案例、定价、客户案例、文档、FAQ、帮助中心、更新日志、关于页面和公开政策。记录：

- 产品类别与核心功能
- 产品承诺的结果
- 官网声称的目标用户
- 免费与付费边界
- 使用前提和明显限制
- 产品使用的行业术语

将这些内容标为“产品方陈述”。把目标用户、痛点和付费理由写成待验证假设，不直接当作结论。

## 2. Google 需求关键词发现

### 七层用户发现漏斗

不要从产品名直接拼接长尾人群。依次扩展：

1. **产品类别**：发现行业、竞品和通用市场语言。
2. **用户任务**：搜索用户想完成什么，不带产品名。
3. **问题原话**：搜索用户自然描述的困难、抱怨和失败。
4. **替代方案**：搜索手工方案、多工具拼接、竞品和忍受问题的人。
5. **触发事件**：搜索需求突然变重要的事件和时点。
6. **角色与行业**：只使用前五层已经发现的真实角色继续验证。
7. **产品与竞品**：研究已进入试用、比价、购买、续费、取消或迁移的人。

搜索词族必须覆盖任务、抱怨、理想结果、触发事件、手工替代、失败/取消/
迁移、购买/比较和用户原话。先从核心广义需求开始发现市场语言，再用已获得
的角色、场景和原话逐步收窄；不要只用超长尾词，以免漏掉完整需求空间。

### 查询规则

- 第一轮先执行不带 `site:` 限定的全网开放查询，观察真实结果出现在哪些平台、
  社区、语言和内容形态；不得一开始就套用固定平台名单。
- 发现阶段尽量使用 2 至 5 个实义词。
- 一次最多组合两个维度，例如“问题 + 角色”。
- 不同时加入产品、国家、行业、角色、场景和功能。
- 超长查询只用于验证已有假设。
- 没有结果时先向上扩大概念，不继续增加限定词。
- 同时搜索支持和反面语言，如 review、complaint、cancel、refund、not worth it、alternative、vs 和 manual。
- 只有开放发现、用户原话或已有线索表明某个平台相关后，才使用 `site:` 查询
  深挖该平台。平台原生搜索存在无需浏览器的公开接口或静态结果时，再用于补足
  搜索引擎索引缺口；需要页面交互、登录或浏览器自动化时跳过并记录覆盖缺口。

每个从 Google 发现的产品记录：query、语言、市场、结果类型、发现日期、
官网 URL，以及对应的用户任务或问题。搜索结果只证明可发现性，不证明用户
提及、使用、付费或评价。

内部从发现阶段起就分开保存四类词，外部也不得混称：

- **用户实际搜索词**：只有用户公开自述“我搜索了……”或可核验搜索日志
  明确出现的查询，才归入此类。
- **用户自然表达**：从用户原话抽取的任务、抱怨、理想结果或替代做法；它能
  帮助构造查询，但不能冒充用户真的在 Google 输入过。
- **研究查询词**：本次研究者实际用于 Google 或站内搜索的查询。
- **合理扩展词**：由用户表达、任务或方案推导、但本次没有真实执行或观察到
  用户输入的候选查询。

## 3. 用户讨论滚雪球发现

每轮都从真实讨论提取：

- 用户自己的问题表达
- 行业术语和缩写
- 新的角色、行业与国家
- 竞品和替代方案
- 触发事件
- 社区、论坛、频道和评价站
- 用户尝试、使用、付费、续费、取消、迁出、迁入、推荐或劝退的产品
- 用户组合、自建或用手工流程替代的方案

对每个新产品或方案保留用户原话、Q 编号和讨论链接，将新词加入下一轮
搜索。不要一次凭空生成全部关键词，也不要把用户提及误写成真实使用。

至少完成三个扩展方向：

1. 从官网进入产品用户讨论。
2. 从问题与替代方案进入尚未使用产品的人。
3. 从负面、放弃和竞品讨论补充反证。

### 动态平台地图

不要预先规定每次研究都去同一批网站。第一轮开放发现后，为每个核心用户群体
建立动态平台地图，记录：用户为什么可能在这里出现、实际找到的讨论、平台
语言/国家、内容形式、可公开访问范围、平台原生搜索是否可用，以及该平台容易
遗漏谁。

对每个已验证为相关的平台分别搜索三类对象：

1. 目标产品、竞品名称及常见拼写变体。
2. 不带产品名的核心任务、问题、抱怨和理想结果。
3. 用户实际采取的行为、变通办法、取消、迁移、退款和放弃。

继续从新讨论里发现新的社区、职业圈、视频频道、评价渠道、商店、本地语言
平台和解决方案。满足“至少四类渠道”只是最低多样性门槛，不能作为停止平台
发现的理由。重要平台无法通过非浏览器方式公开完整访问时记录缺口，但仍检查
是否存在合格的范围有限证据；不注册、不绕过限制，也不能把“无法访问”写成
“没有讨论”。

### 讨论证据分层审查

先按 `evidence-standard.md` 判断当前要证明的是个人经历、重复模式，还是整场讨论
的主流、分歧和认同度，再选择相匹配的证据范围。

- **完整讨论证据**：读完主帖、全部通过非浏览器方式公开取得的顶层评论和回复，
  检查可取得的主要排序、父子回复、质疑、纠正、推广和反对意见。只有这一级可以
  概括整场讨论中的主流、分歧、最高赞或代表性观点。
- **范围有限证据**：没有读完整场讨论，但完整取得一篇主帖或某条独立评论、
  理解它所需的父级/直接回复、平台、日期、点赞和使用语境。只用于证明该用户的
  身份、场景、行为、痛点、损失、决策或结果；不得写成评论区或社区共识。
- **受限线索**：只有搜索摘要、截断评论、评分总数、第三方转述、标题、删除残片
  或缺少必要上下文。只用于发现关键词、用户群体、平台、产品和其他来源。

内部为每个用户来源记录：证据范围、实际读取边界、平台显示的评论量和点赞、
已经检查的父子上下文或排序、第一手/二手状态、允许支撑的结论、禁止外推的结论。
若某条范围有限证据后来取得整场讨论内容，可升级为完整讨论证据；反之不得仅因
评论点赞高就把它升级为社区代表性证据。

已删除且不再公开的内容只记录删除标记，不注册、不绕过限制。搜索摘要不能直接
进入正式报告，但如果能够沿链接取得完整证据单元，可以重新判定资格。

每判定一个完整讨论证据、范围有限证据或受限线索，立即写入唯一来源总清单，
记录直接链接、证据范围、实际读取边界、允许结论、禁止外推、平台、日期、点赞、
用户群体、主要观点、支持/反证/低信息/推广状态、完整调研总结、研究观点/局限
和关联问题。同时把所有实际使用的产品官网、
功能、用例、定价、案例、文档、政策、官方规则与背景来源写入同一外部证据总清单
的对应分类。最终报告不得只挑代表来源：总清单必须先于故事和问答完整展示；
总清单中的每个完整讨论证据和范围有限证据还必须至少在一个相关故事或问题下
出现。报告分别声明三类数量；正式用户证据总数等于前两类去重链接之和，受限
线索不得混入。

## 4. 解决方案资格

按 `evidence-standard.md` 为每个 SOL 记录发现路径、状态证据和以下状态：

- Google 可发现
- 用户提及
- 真实使用
- 真实付费
- 推广为主
- 当前不可用

Google 发现与用户提及是两个互补入口，任何单一路径都不能定义“全部市场”。
每个被纳入方案总清单的 SOL 都必须建立独立逐产品档案并完成公开页面允许范围内
的营销、细分用户假设和功能覆盖研究。没有真实使用证据时，仍分析产品方怎样
定位和销售，但用户优点、缺点、实际效果和付费价值必须明确保持未知。

## 5. 逐产品档案

对公开研究范围内找到的每个 SOL 都建立独立深度档案，固定记录以下 18 项：

1. 发现路径与当前状态。
2. 在需求供给生态中覆盖的环节。
3. 产品页面反推的细分用户：角色、行业、组织规模、地区/语言、成熟度。
4. 使用者、建议者、决策者、付款者和审批者假设。
5. 主打任务、触发事件和理想结果。
6. 差异化叫卖点与希望用户记住的一句话。
7. 从搜索入口、首屏、用例、功能、证明、定价到 CTA 的公开营销链路。
8. 利益、风险、速度、便利、信任、价格或身份等营销诉求。
9. 社会证明、异议处理和信任设计。
10. 定价包装、价值单位、试用/演示入口和付费触发假设。
11. 核心功能、覆盖工作流、实现深度、前提与约束。
12. 对已验证用户痛点的覆盖：直接、部分、间接、未覆盖、新代价或未知。
13. 真实用户获得的正面结果。
14. 抱怨、失败、隐性成本和版本/市场差异。
15. 续费、取消、迁移和替代行为。
16. 适配人群、不适配人群和仍未完成的步骤。
17. 值得学习的产品或营销做法。
18. 可能切入的不足、反证、证据覆盖和未知。

细分用户、功能/实现深度、价格与约束、差异点等来自官网的信息必须标为
“产品方陈述”或“页面反推假设”，不能冒充用户事实。真正触发付费的结果只可由 P3/P4 证据
支持。体验、优缺点、实际结果、续费、取消和迁移只使用具有真实使用或真实
行为的 Q。任何项目缺少相应证据时写未知，不得推测填满档案。

逐个产品分别研究并引用 S/Q/SOL；不能先做一张竞品表，用表格替代单品
深挖。只有全部独立档案完成后，才能制作内部跨产品矩阵。目标是覆盖本次
研究范围内发现的所有方案，并让研究与呈现深度随证据变化；不是只挑少数
代表产品，也不是声称无限穷举完整市场。

上述 18 项只作为内部研究检查，不能把它们连同官网功能和评价摘录直接拼成
外部内容。

内部逐产品档案以营销策略和痛点覆盖为双主线：把产品放回需求供给生态，判断
它覆盖哪一段、主要差异化叫卖点、核心结果和页面反推的细分用户；再完整追踪
Title/Meta、首页首屏、角色/用例页、功能页、案例与社会证明、异议处理、定价
包装、CTA 和公开试用/演示入口，解释每个节点如何筛选用户、建立信任、解释
价值、降低风险并推动下一步。

把页面反推的细分用户作为新一轮用户研究假设：用对应角色、行业、任务、触发、
购买者和产品名组合继续开放搜索和平台原生搜索。若真实用户身份、任务和决策链
相符，可作为既有群体的补强或新群体线索；若不符或找不到，不得把营销画像写成
真实用户画像。产品研究因此可以反哺用户研究，但不能取代用户研究。

对需求证据池中的每个材料性痛点，逐产品建立内部覆盖映射：产品宣称提供什么
功能或结果、覆盖工作流哪一步、覆盖深度与前提、真实用户是否确认有效、是否只
解决一半、是否转移成本或产生新问题，以及公开材料仍无法确认什么。

对每个产品分别提取网页 Title、Meta Description 和首页 H1 的原文、忠实中文
翻译、字段位置与官网直链。三项都要核验；不存在或无法读取时明确写明。再从每个
关键营销节点选取足以支撑细分用户、差异化、信任和转化判断的代表文案及直链，
但不能用大量官网文案淹没已经消化过的营销策略分析。

### 产品理解完成条件

产品理解分为两条独立轴线，不能互相替代：

- **产品方与营销理解**：依靠公开官网和营销链路，完成定位、细分用户假设、
  差异化叫卖点、功能/工作流覆盖、信任与异议处理、定价包装和 CTA 分析。
- **真实用户体验理解**：依靠真实使用材料，验证实际效果、优缺点、付费价值、
  隐性成本、续费/取消/迁移和未满足任务。

即使没有真实使用证据，也必须对每个找到的产品完成公开页面允许范围内的第一条
轴线，不能降成只有名称和链接的简卡；但第二条轴线必须明确写“证据受限”。

每个具有真实使用证据的产品都必须先综合形成一条连续理解链：为什么发现 →
期待 → 设置/使用过程 → 得到结果 → 付费价值 → 正/负情绪 → 隐性成本 →
续费/取消/迁移 → 实质差异 → 仍未完成任务。每一环都要区分产品方陈述、
用户直接事实、综合推理、反证和未知。

每条产品体验链在内部绑定相容的群体、角色（使用者、购买者、付款者和
审批者）、市场、时间/版本与使用状态。不同群体、角色、市场、版本或使用
路径不能硬拼成一条经历；存在实质差异时拆开讲。跨用户材料只能综合共同
模式，不能假装是同一真实个人连续发生的因果经历。

产品理解三态按以下门槛判断：

- **理解充分**：至少有 3 名相容且按 U 去重的真实使用用户、2 个独立来源
  页面，证据覆盖设置/使用过程，并至少覆盖价值结果或失败、续费、取消、
  迁移中的一项；同时理解链的材料性判断已有相容证据或明确边界。
- **继续研究**：产品仍属重要方向、方案发现尚未饱和，且上述人数、来源、
  使用过程或结果链仍有可追查缺口。
- **证据受限**：研究已按饱和或失败处理停止，但仍未达到理解
  充分门槛；停止研究后的对外输出中，关键环节只有官网陈述或未知时也必须
  这样标记，不得编成完整体验。

没有真实使用证据的方案仍完成产品方与营销理解，但真实用户体验按证据受限处理，
不进入完整体验门槛；这不等于从第十二、十三、十四问删除或简写该方案。

缺少关键环节时继续研究或明确保留未知，不得用功能列表或单条评价补齐。
只有达到理解充分，才可写完整“用户视角体验产品”。

### 在三段式报告中呈现逐产品理解

外部第一部分先完整列出逐产品证据来源；第十二、十三问必须覆盖本次公开
研究范围内发现的全部方案，不得只挑
代表产品，也不得用内部 18 项档案、采集清单或矩阵代替逐产品回答：

- 第十二问逐一列出全部发现方案、直接产品来源、解决步骤和证据状态。仅可发现、
  用户提及、真实使用和真实付费仍在内部严格区分；每个产品展示网页 Title、
  Meta Description、首页 H1 的中英文原文。
- 第十三问先依据每个产品的功能介绍、卖点、定价、文档和页面文案，逐一说明
  它在供给生态中的定位、页面反推的细分用户、差异化叫卖点、营销链路、功能
  覆盖、使用前提、定价逻辑和限制；再在同一产品下单独归纳真实用户评论，说明
  已解决、部分解决、未解决、新增代价或未知，以及使用价值、失望、继续或离开、
  隐藏成本和遗留痛苦；最后分别给出可学习做法、可能切入点和反证。证据受限的
  产品只回答已知片段与未知；没有合格真实使用评论的产品明确写“未找到”，不得
  删除或补写。不使用用户评论替产品补功能，也不把产品方承诺写成已验证效果。
- 第十一问只回答目标网站本身的真实用户评价，不得用类别需求、竞品用户或产品
  官网宣传补足目标产品口碑。

产品再多，仍按上述层级逐一覆盖；跨产品机会比较只能建立在每个产品已经完成
相应层级理解后。外部用户证据列出全部完整讨论证据和范围有限证据的直链、
完整调研总结和研究
观点/局限，不展示逐字原话；产品证据展示逐产品 Title、Meta Description、
首页 H1 双语原文及少量必要显眼文案，不显示内部推理账本。

## 6. 渠道覆盖

平台名单必须通过开放搜索、用户原话、产品使用路径和滚雪球动态发现，不预设
固定站点。根据实际用户群体检查不同采样机制：长篇讨论社区、专业或职业社区、
软件/消费评价渠道、应用或扩展商店、视频及其评论区、即时社交内容、产品帮助
社区、问答或行业垂直社区，以及目标市场的本地语言平台。这里是渠道类型检查，
不是每次照抄的平台清单。

至少覆盖四类真正独立的渠道，但必须同时满足：每个核心群体已经建立平台地图；
开放发现得到的平台已逐一核验；公开可访问的平台尽量完成原生搜索；新平台和
新社区也进入后续扩展轮次。不要让单个平台提供超过全部证据的 50%。不同站点
只有在覆盖人群和采样机制存在实质差异时才算不同渠道类型，不得用多个同质社区
凑数，也不得在满足四类后停止寻找。

## 7. 多语言与国家研究

识别产品主要市场，并为每个重要市场：

1. 翻译核心任务、问题、触发事件和替代方案。
2. 用当地用户自然说法替换机械翻译。
3. 搜索本地论坛、评价站、视频和社交平台。
4. 分开记录文化背景、工作流程、监管环境和价格敏感度。
5. 无法覆盖时将该市场标为研究缺口。

不得用英语社区的结论代表全球用户。

## 8. 时间与版本切片

记录证据日期，并尽量确认当时的功能、定价、政策和产品版本。遇到新旧评论冲突时检查：

- 产品是否已经修复或删除功能
- 定价或套餐是否变化
- 用户是否来自不同国家或方案
- 评论是否针对不同使用场景

把长期存在的问题与已经过时的历史问题分开。

## 9. 用户群体覆盖与沉浸重建

为每个候选群体记录：

| 字段 | 内容 |
|---|---|
| 群体编号 | G01、G02…… |
| 发现路径 | 官网、问题词、替代方案、竞品或社区 |
| 背景证据 | 自述角色、行业、国家、公司规模、技术水平 |
| 核心任务 | 用户要完成什么 |
| 触发事件 | 为什么现在必须解决 |
| 当前方案 | 手工、拼接工具、竞品或忍受问题 |
| 证据覆盖 | 原话数、独立用户数、渠道数 |
| 当前状态 | 已验证、初步验证、待验证或被反证 |

群体标为“已验证”至少需要 10 条合格原话、5 名按 U 去重的独立用户和 2 类
渠道。未达到门槛时只能标为初步验证或待验证；存在足以推翻群体假设的强反证
时可以标为被反证。

同时寻找产品用户、竞品用户、手工用户、拼接工具用户、尝试后放弃者、暂时不解决者，以及使用者、购买者、付款者和审批者。

### 用户沉浸重建

用户沉浸重建先用于内部形成完整理解，不在采集过程中同步生成外部故事。

先按角色、国家/文化、日常工作流、利益、决策权、付款关系、技术水平和需求
阶段拆分实质不同的用户群体。只有这些维度没有实质差异时才允许合并；不得为了
缩短报告把使用者、决策者、付款者或不同制度环境的人压成一个平均用户。发现
几个达到核心群体门槛的群体，第二问就必须写几个独立故事。

### 用户理解完成条件

每个核心群体写故事前，内部必须形成完整理解链：公开身份与文化线索 →
原工作流 → 触发 → 受阻 → 表面抱怨 → 底层原因 → 情绪线索 → 利益 →
变通 → 代价 → 决策心理 → 付费触发 → 反证/不同选择。每一环都要由相容的
原话、行为或背景证据支持，并记录未知、冲突和不同路径。没有形成这条理解链，
不得开始写故事，也不得把群体档案字段按顺序改写成故事。

用户理解三态不替代群体验证状态，按以下规则判断：

- **理解充分**：完整理解链由相容证据支持，并达到核心群体至少 10 条合格
  原话、5 名按 U 去重的独立用户和 2 类渠道的门槛；可以写证据驱动的完整
  代表人物故事。每个故事通常不少于 1500 个中文字，不得用一两段概述代替。
- **继续研究**：群体属于重要方向、证据尚未饱和，且理解链或数量/渠道门槛
  仍有可追查缺口。
- **证据受限**：研究已按饱和或失败处理停止，但理解链或门槛
  仍不足；只输出证据受限的用户理解、来源链接与调研总结、未知和不同选择，
  不强行写完整故事。

### 情绪线索

主动留意强烈措辞、反问、讽刺、重复求助，以及退款、取消、迁移、回到手工、
降级和放弃等行为。行为只作为情绪线索，不能单独证明具体情绪；命名情绪时
必须按 `evidence-standard.md` 用原话语气、措辞、行为信号或独立语境交叉
印证。内部账本记录原话的语气怎样支持该推理、有哪些替代解释和反证；外部
写作使用与证据强度相称的谨慎措辞。

用户理解充分后，可以创作证据驱动的虚构代表人物，包括身份背景、国家或
文化处境、场景、情绪、损失、决策、因果、结果和叙事顺序。创作必须遵循
`evidence-standard.md` 的相容性、去识别、证据强度和就近解释要求：不冒充
单一真实个人或真实采访，不脱离相容证据，不把故事化细节写成已证实事实，
不填平关键未知。内部账本把每个材料性细节映射到相容证据组；外部不得显示
Q 等内部编号、映射解释或逐字原话，只在第二问每个群体故事下列出全部相关
来源直链和逐链接调研总结。

写作前逐项回查人物故事里的重要身份/文化背景、情绪、利益、损失、决策、
因果和结果：每一项都必须在内部映射到具体原话或相容证据组。只能作为叙事
衔接的细节要在内部明确标成故事化创作；既无证据又会改变读者判断的细节必须
删除或保留为未知。外部故事不展示推理说明和用户原话，但不得省略参与这些
理解的任何来源链接或对应调研总结。

每个核心群体故事通常不少于 1500 个中文字，采用第三人称贴身视角，让读者只
跟随人物当下能够看到、想到、担心和权衡的内容。用连续场景写透：人物的生活/
工作背景和文化处境 → 平时怎样
完成任务 → 什么事件让问题突然变得重要 → 卡在哪个具体步骤 → 情绪怎样变化 →
损害了什么利益和关系 → 当前怎样绕路 → 付出哪些时间、金钱、风险和机会成本 →
怎样搜索、比较和判断可信度 → 谁使用、谁决定、谁付款 → 什么结果让其愿意付费
→ 理想结果和仍然未知。故事必须让外行人能够在该人物的位置上理解其思考过程，
不能写成身份字段、痛点清单、产品画像摘要或冷静的研究结论拼盘。

从一个具体且有压力的时刻进入故事，不先解释人物“有哪些痛点”。用动作、受阻、
时间流逝、反复尝试和选择冲突推动叙事，让情绪从发生的事情里自然长出来。至少
写清一条情绪变化链：原本的期待或责任 → 第一次失败 → 自救或变通 → 再次受阻
→ 代价逼近 → 开始搜索、怀疑、比较或放弃。不要只添加“焦虑、痛苦、愤怒”
等形容词，也不要为了煽情虚构精确事实。

把利益和代价写成故事的因果核心：问题正在威胁谁依赖的结果、人物的成绩、收入、
职业信誉、身体负担、关系责任、机会或时间自主；人物为什么既想尽快解决，又会
因价格、风险、准确性或信任问题退缩。关键时刻可以写人物可能怎样想，但必须是
证据约束下的综合推理，不能加引号冒充真实用户原话。

整篇围绕一个具体的虚构综合人物推进，不在叙事中途退回“这类用户”的抽象画像。
至少形成三个前后相连的场景和两次内心冲突或认知变化；产品、功能、比较和证据
只能在人物实际遇到它们的时刻进入。删掉不会改变人物选择、代价或理解的装饰性
细节，也删掉暂停故事去解释产品功能的段落。

每个故事必须解释三层需求：用户嘴上要的功能、真正要完成的任务、以及他最终
想保护或获得的底层利益与心理结果。底层需求可能涉及掌控感、确定性、可信结果、
身份表现、时间自主、风险降低或关系责任，但必须由语言、行为、损失和决策证据
共同支持，不能套用心理学词汇。关键转折后就近穿插相关直链；用一行自然、具体
的研究性总结说明该来源中的处境、行为或代价，再补充必要的研究观点/局限，让
证据像故事因果的一部分，而不是插入一张独立证据卡；不展示用户原话，不把全部
证据只堆到故事末尾。

## 10. 需求与付费决策链

逐群体回答：

- 用户原本在完成什么任务？
- 什么事件触发了需求？
- 具体在哪一步受阻？
- 问题为何产生，涉及什么利益？
- 不解决会损失什么？
- 当前怎样解决，付出多少时间、金钱、风险、学习和机会成本？
- 为什么开始寻找产品？
- 谁使用、谁提出购买、谁付款、谁批准预算？
- 什么证据让其相信产品？
- 为什么付费、续费、升级、取消或拒绝？

只把 P3、P4 当作强付费证据。

## 11. 验证产品实际表现

本节只适用于具有真实使用证据的 SOL，并以对应用户原话为依据。主动收集：

- 用户认为最有价值的结果
- 难用、错误、限制和隐藏成本
- 取消、退款、降级与迁移原因
- 宣传与实际体验的差距
- 尚未满足的场景
- 不适合该产品的人群
- 选择竞品或不解决问题的原因

不同意见必须与主流结论并列，不得为了形成整齐故事而删除矛盾。

## 12. 机会证据链

机会证据链的目标结构是：重复需求抱怨 → 现有方案仅部分解决或制造新伤害
→ 变通/迁移/搜索 → 具体损失 → 付费或行为证据 → OPP。

机会线索按 `evidence-standard.md` 分级流转：

- 缺少“具体受阻步骤”或“实际损失/替代或变通成本”任一条件时，只能记为
  问题线索，不得称为机会假设。
- 两个条件都具备、但尚未达到候选机会数字门槛时，称为机会假设。
- 达到候选机会数字门槛后才称为候选机会；继续满足相应门槛和反证要求，才可
  升级为已验证机会方向或强产品信号。

候选机会缺少完整付费链时不得因此排除，也不得用官网主张或推测补写缺失
环节。已有链路环节必须引用 Q/S/SOL/C，并主动寻找能够说明问题已解决、
不持续、不值得付费或不愿切换的反证。

### 机会理解完成条件

机会分析必须等待本次研究范围内的核心用户群体和所有已发现方案完成相应层级
理解与呈现，且方案发现达到公开范围饱和。证据受限群体或
方案只需完成其对应层级，不得因无法补足完整故事或体验而无限阻塞机会分析。
写作前先综合：
用户真正想得到的结果 → 各方案解决到哪一步 → 反复失败的原因 → 情绪/利益
代价 → 搜索/付费/迁移/变通 → 最小新产品结果 → 反证 → 用自然语言说明
证据强弱。内部的样本计数、等级和机会门槛仍用于限制结论强度，但不能把计数、
等级或证据链字段直接改写成机会叙述。

机会理解三态按以下规则判断：

- **理解充分**：所有已发现方案均已完成相应层级理解，方案发现已达到公开范围
  饱和，并能用相容证据解释上述综合链、反证和自然语言证据强弱。理解充分
  不等于必须存在候选机会；可以最终得出“本次没有足够机会”。
- **继续研究**：重要用户或方案方向尚未饱和，且仍有合法公开线索可追，并且
  上述综合链仍有可追查缺口。
- **证据受限**：研究已停止，但现有证据不足以解释关键失败原因、代价、最小
  新产品结果或反证；只保留问题线索或机会假设及其限制，不写完整机会叙述。

若无法解释为什么现有方案反复失效、新结果为何足够小且有价值，或反证如何
限制结论，就继续研究或按上述层级降级，不得用整齐叙事掩盖缺口。完成全部
分级后，即使没有任何候选机会，也允许以“本次没有足够机会”结束研究。

## 13. 研究日志

每轮记录：

- 查询词、语言、平台和日期
- 全网开放发现出现的平台、按用户群体建立的平台地图和遗漏方向
- 每个平台执行过的产品词、问题词、行为词和原生搜索范围
- 完整讨论证据、范围有限证据和受限线索的分别判定；每条来源的实际读取边界、
  允许结论、禁止外推、点赞、主要立场和必要上下文
- 正式用户证据总数、每个来源的唯一链接与调研总结、关联问题，以及全篇输出
  是否已经逐项列全
- 本轮使用的所有网页是否均由非浏览器方式取得；无法取得整场讨论的页面是否
  正确降为范围有限证据或受限线索，而不是被错误排除或错误外推
- 新发现的群体、场景、问题、替代方案与付费因素
- 没有找到证据的假设
- 排除的来源及理由
- 本轮是否仍出现重要新增

没有找到证据不等于需求不存在，只能说明本次公开研究无法支持该判断。

## 14. 方案发现饱和

达到适用的需求证据数量下限后继续扩展：窄范围研究至少 50 条；涉及 3 个及以上
核心群体、多个国家/语言市场或多个实质任务时至少 100 条。只有连续三轮既没有
新的合格用户原话、新平台
或新社区，也没有新的核心群体、任务、触发事件、方案类别、重要产品、工作流
差异、抱怨簇、付费因素或机会反证，才可在已覆盖的公开证据范围内停止。每轮
必须同时包含开放搜索、已发现平台的定向搜索、公开可访问时的平台原生搜索和
用户原话滚雪球；只在同一熟悉平台继续翻页不算完整扩展轮次。

合格原话不设固定数量上限；只要仍能找到新的合格原话、平台或重要内容，并且
仍有合法公开线索可追，就继续收集。只有达到上述公开范围饱和，或触发下一节
的失败处理边界，才停止扩张，并披露未覆盖的市场、语言、渠道、群体、讨论
分支和方案方向。

## 15. 失败处理

- **网站不可访问**：尝试公开子页面和第三方来源，列出无法查看的内容。
- **产品过新**：扩展到类别、竞品和底层问题，但不得把品类用户冒充产品用户。
- **平台受限**：停止访问，不注册、不绕过限制。
- **身份不明**：保留未知，不推断敏感属性。
- **来源矛盾**：检查版本、国家、套餐和群体差异；无法解释则保留矛盾。
- **单平台集中**：标记偏差并继续寻找其他渠道。
- **推广嫌疑**：降低等级或排除。
- **无联网能力**：停止真实用户调研，说明需要可访问材料或联网能力。
