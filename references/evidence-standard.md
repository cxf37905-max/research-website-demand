# 证据标准

## 1. 有效来源

将能够公开访问、定位原文并为当前结论提供足够语境的完整讨论或范围有限证据
单元计为有效来源。证据单元可以是整个讨论，也可以是能够独立定位并完整取得
必要上下文的一篇主帖或一条评论。优先使用用户主动发表的论坛讨论、社区帖子、
评论区、评价站、应用商店、视频评论和公开社交内容。

不要把以下内容计入有效用户证据：

- 官网匿名短评、客户 Logo 或无法核验的成功数字。
- 纯营销、赞助、联盟推广或复制聚合内容。
- 只有星级、情绪词或一句空泛判断的短评。
- 搜索结果摘要、AI 摘要或已经删除页面的残片。
- 无法确认原始语境、日期或发布位置的转述。

官网、媒体和行业报告可以作为背景资料，但必须标为间接证据。

推广内容、联盟文章和聚合页只能用于发现线索，不能单独证明用户需求、
真实使用、付费或产品效果。重复转载只保留最早可定位的原始来源；找不到
原始来源时降为间接证据，不计为独立来源。

## 2. 合格用户原话

一条合格原话应至少揭示下列一项：身份背景、具体任务、触发事件、问题、原因、利益、损失、替代方案、购买权衡、实际使用结果或未满足需求。

- 保留完整、自成语义的原帖或评论。短评论原则上引用整条；长评论至少保留
  与当前问题相关的完整连续段落，并明确标注省略的是无关部分。不得把同一位
  用户的一段连续经历拆成多条碎片，也不得用省略号拼接出原文没有的因果。
- 保留原语言原话并提供忠实的简体中文翻译。
- 附讨论背景、平台、日期、直接链接，以及公开可见的点赞数或排序位置。
  无法看到票数时不得称为“最高赞”或猜测热度。
- 转述不得放入引号冒充原话。
- 同一用户的多条内容不得冒充多个独立用户。
- 明确确认属于同一用户后，跨平台重复发布的相同经历合并计数，并保留全部
  可核验链接；无法确认时遵循后文的潜在重复组规则。
- 无法确认是否真实使用过产品时，明确记录未知。

### 2.1 讨论证据资格与结论范围

证据资格按“实际完整取得的证据单元”判断，而不是要求每个来源都必须读完整个
大型讨论。结论能写多大，取决于实际读到多大范围。研究过程仍不得打开或控制
可见浏览器、无头浏览器、Chrome、应用内浏览器或其他浏览器自动化；只允许使用
搜索结果、普通网页读取、直接 HTTP、公开 API、RSS、JSON 和结构化数据等不启动
浏览器进程的方式。

#### 完整讨论证据

只有完成以下审查，才可把整个讨论当作证据单元：

- 阅读主帖全部正文和可见编辑内容。
- 阅读全部通过非浏览器方式公开取得的顶层评论和回复分支。
- 检查平台能够通过非浏览器方式返回的主要排序，例如最佳、最高赞、最新和争议。
- 检查主要立场、重要反对观点、质疑、纠正、推广、删除标记和跑题内容。
- 记录页面显示的评论数量、公开点赞数、实际读取范围和仍不可访问的边界。

完整讨论证据可以支撑“这场讨论中主要出现了哪些观点、哪些观点得到较高公开
认同、存在哪些分歧”的结论，但仍不能代表整个平台、整个职业或整个市场。

#### 范围有限证据

没有读完整个讨论时，只要满足以下条件，一篇完整主帖或一条独立评论仍可作为
正式的范围有限证据：

- 能够定位原始页面或该评论的永久直链，而不是搜索摘要或第三方转述。
- 完整取得该主帖或评论本身，未把截断片段当成完整陈述。
- 对评论至少取得理解它所必需的父级内容、直接回复或附近质疑；没有相关回复时
  如实记录。
- 能确认平台、公开日期和发言位置；点赞隐藏时写隐藏。
- 能从公开内容判断这是第一手经历、二手转述、产品提及还是使用状态未知。
- 当前结论所需的身份、场景、行为、问题、损失、决策或结果具有足够上下文。

范围有限证据只能支撑该用户或该完整证据单元明确表达的具体经历。它可以用于
重建用户身份、场景、情绪线索、痛点、损失、变通、购买或使用结果，也可以与
其他独立来源交叉归纳重复模式；但不能单独支撑“整个评论区都同意”“这是社区
共识”“多数用户如此”或“这是本帖最具代表性的观点”。

如果该评论的点赞数能够直接核验，可以说“这条具体评论显示 X 点赞/净赞/综合
分数”；只有同时核验整场讨论的相关排序和其他高赞观点后，才能称为该讨论中的
最高赞、主流或最具代表性观点。

#### 受限线索

以下内容不进入正式用户证据计数，只用于继续发现：搜索结果摘要、被截断的帖子
或评论、只看到评分/评论总数而看不到内容、第三方转述、无法定位原始语境、缺少
必要父级上下文、无法确认是否真实使用，以及仅有标题或删除残片的页面。

受限线索可以用于提取关键词、发现用户群体、平台、产品、竞争方案、原始页面和
下一轮查询方向，也必须在外部证据总清单中说明发现内容、限制和利用方式；但不得
直接支撑用户身份、痛点、损失、付费、产品体验、群体认同或机会结论。

#### 对外展示

外部不展示逐字用户原话。每个完整讨论证据和范围有限证据必须提供直接链接，
标明证据范围，并紧跟一段大白话调研总结：谁在什么社区、公开身份与处境、发生
了什么、主要观点、痛点/利益/情绪/行为/决策，以及这条材料能够支持什么、不能
支持什么。只有完整讨论证据才能总结整个评论区的认同与分歧；范围有限证据只能
总结实际读取到的直接上下文，不能假装理解了整场讨论。

## 3. 内部研究账本与追踪编号

研究过程必须维护一份**内部研究账本**。内部研究账本继续使用编号、计数、
等级和审计字段完成证据追踪、三类证据池归档、用户与来源去重、结论支持与
反证、解决方案资格判断、机会门槛判断和结论晋级。内部严谨性不得因为外部
报告改用自然语言而降低。

使用稳定编号：

```text
S01 = 来源页面或讨论串
Q01 = 合格用户原话
U01 = 内部稳定用户去重键（仅用于内部研究账本）
G01 = 用户群体
C01 = 关键结论
SOL01 = 被研究的解决方案
OPP01 = 候选或已验证的机会点
```

每条 Q 关联一个 S、一个 U 和至少一个 G。每个 C 列出支撑与反驳它的 Q，
并在每个 Q-C 关联上记录支持或反驳的 A/B 证据等级。每个 SOL 关联发现
它的 S、涉及它的 Q 和适用 G，并记录资格状态及状态证据。
每个 OPP 关联至少一个 G、描述未满足缺口的 C、支撑与反驳它的 Q/S，
以及用于比较现有解法的 SOL。内部研究账本为每个用户故事列出对应的 G、
Q 和 C。不得输出无法追踪到证据或明确推理的重要结论。

内部研究账本中的每条证据及其关联记录：

- 原语言原话与忠实中文翻译
- 平台、URL、发布日期和访问日期
- 当时的产品版本、价格或政策，无法确认时写未知
- 用户公开自述的角色、行业、国家和其他背景线索
- P0 至 P5 付费等级
- 每个 Q-C 关联支持或反驳的 A/B 证据等级
- 来源或材料的 C 级、假设分类（适用时）
- 关联群体与支持或反驳的结论

另维护一份**证据来源总清单**。每个完整讨论证据、范围有限证据和受限线索保留
一个唯一直接链接，明确记录证据范围、实际读取边界、允许支撑的结论、禁止外推
的结论，以及有效支持、反证、低信息、疑似推广或排除原因。一个讨论串包含多条
评论时默认计为一个来源；只有独立评论存在可直接定位的永久链接、被单独完整取得
必要上下文且承担不同用户经历时，才作为独立范围有限证据计数，不能用同一讨论的
多条评论机械虚增来源数。受限线索、搜索结果页、产品官网和未打开的页面不计入
正式用户证据总数。

### 外部报告层

**外部报告不得显示内部编号**、内部用户去重键、潜在重复组键、S/Q/U/G/C/
SOL/OPP、A/B/C 证据等级、P0-P5 付费等级、门槛代码或审计字段。正文、
脚注和证据列表都遵守这一规则。回答正文用自然语言给出已经消化的理解；不得
把内部标签换一种缩写后继续暴露。

正文不得用编号代替可点击直接来源，也不得要求读者根据 Q 编号寻找证据。
外部不展示用户逐字原话。报告先按第 16 节输出完整证据总清单，再输出全部核心
用户群体的沉浸故事，最后回答固定 14 问；故事和问答中的材料性理解仍穿插相关
来源直链、逐链接调研总结和研究观点，以及逐产品网页 Title、Meta Description、
首页 H1 双语原文。内部账本
与外部报告是一对多的映射：一段自然语言回答可以由多条内部记录支撑，但所有
追踪、映射、计数、去重、反证和晋级仍在内部账本完成。

## 4. 三类证据池

三类证据池必须分开记录，不能互相替代：

- **需求证据池**：用户对任务、触发事件、问题、损失、变通方式、搜索、
  放弃或购买行为的直接陈述。产品官网不能替代需求证据。
- **目标产品证据池**：能够确认用户实际接触、使用、付费、续费、取消或
  迁移目标产品的证据。竞品评论不能替代目标产品口碑。
- **解决方案证据池**：竞品、手工流程、多工具拼接、服务商或暂不解决等
  方案的发现、使用、付费与效果证据。

同一来源可以向多个证据池提供不同记录，但每条记录必须标明所属证据池，
且不得把某一池的证据直接外推成另一池的结论。

## 5. 证据等级

A/B 是 Q 对具体 C 的支持或反驳证据等级，必须记录在每个 Q-C 关联上，
而不是固定在 Q 上。同一条 Q 对范围较窄结论的支持或反驳可能为 A 级，
对范围更宽的结论可能仅为 B 级。

- **A 级**：用户具有足以直接支持或反驳当前结论的完整自述语境；判断该
  支持或反驳所需的关键身份、场景、使用状态、行为和结果均不得缺失。
- **B 级**：内容来自真实讨论，但支持或反驳当前结论所需的关键身份、场景、
  使用状态、行为或结果任一缺失。此类证据不可升为 A 级。
- **C 级**：官网、媒体、行业资料或其他间接证据。
- **假设**：缺少直接证据，只能作为后续验证方向。

C 级和假设可以保留为来源或材料级分类；它们参与具体 C 的推理时，必须
在该 C 的证据链中注明分类、作用和局限。

官网自述不能单独把用户需求结论提升为高置信度。重要结论尽量获得两个独立渠道的用户证据。

## 6. 付费证据等级

- **P0**：只讨论需求或问题。
- **P1**：表达购买意愿。
- **P2**：正在试用、询价或比较价格。
- **P3**：明确表示已经付费。
- **P4**：明确表示续费、升级或扩大使用。
- **P5**：取消、退款、降级或拒绝购买。

只有 P3 和 P4 可以作为强付费证据。P0 至 P2 只能证明需求或意愿；P5 用于研究购买阻力、价值落差和流失原因。

## 7. 解决方案资格状态

每个 SOL 必须记录发现路径和状态证据。发现路径应为搜索词与结果页，或
用户原话与讨论链接。状态可以并存，但必须分别给出证据：

- **Google 可发现**：能通过公开搜索结果定位；只证明可发现，不证明使用。
- **用户提及**：用户主动提到该方案；只证明认知或考虑，不证明使用。
- **真实使用**：用户明确说明实际使用过程或结果。
- **真实付费**：用户明确说明购买、订阅、续费或扩容。
- **推广为主**：主要证据来自官网、赞助、联盟营销或推广账号；降权处理。
- **当前不可用**：已下线、停止服务、无法注册或在研究市场不可获得。

只有存在真实使用证据时，才可归纳该方案的用户优点、缺点和实际效果。
真实付费但无法确认已经使用时，只能证明购买行为，不能证明产品体验。

## 8. 未满足缺口证据

将一条材料计为未满足缺口，必须同时满足以下两个条件：

- **条件一：具体受阻点或未实现结果**：明确指出未完成的任务步骤或未实现
  的预期结果；
- **条件二：实际损失或替代/变通成本**：至少具有以下一项：可辨认的时间、
  金钱、风险、收入、
  机会或情绪损失；或者为绕过问题采用手工操作、多工具拼接、迁移、放弃
  等方案产生的替代或变通成本。

缺少条件一或条件二时，只能记录为待验证的问题线索，不得计入缺口或机会
门槛。每个缺口还必须记录它是否在多个产品或多类解决方案中重复出现。
只有情绪表达或空泛差评时不得计入缺口；单一产品偶发故障不得直接上升为
跨市场机会。

## 9. 机会点资格与数字门槛

- **候选机会**：至少 3 位独立用户、2 个独立来源页面，并有明确损失或
  变通成本。未达到时只能称为“机会假设”。
- **已验证机会方向**：至少 8 位独立用户、3 种渠道类型；同一缺口在至少
  3 个产品或 2 类解决方案中重复；具有明确损失；并出现至少 3 个可核验
  的行为信号，例如主动搜索、付费、迁移、手工变通或放弃。
- **强产品信号**：满足已验证机会方向门槛，并同时证明问题当前仍持续、
  跨方案仍未解决、存在预算或付费证据、用户具有主动搜索或切换意图，且
  反证不足以推翻该方向。

未达到相应门槛时必须降级措辞，不得使用“已验证”“强需求”或“强产品
信号”。样本计数只约束结论强度，不代表统计抽样，不得外推市场规模、
用户比例或普遍性。

每个 OPP 的内部研究账本必须主动执行并记录反向查询，包括查询词、检索渠道、
时间范围、对应用户群体、产品版本或状态，以及同群体、同时间范围内的反例。
反向查询至少寻找：问题已经解决、现有方案足够、没有预算、价格不可接受、
不愿切换或切换成本高于收益。可信反证若不能由群体、版本、场景或时间差异
合理解释，机会必须降级；不得只把反例列在旁边而维持原结论强度。未搜索到
反证只能写成“在本次已检索范围内未发现反证”，不能写成“没有反证”。

## 10. 数量、多样性与去重

- 至少 25 个有效用户证据来源页面或讨论串。C 级官网、媒体和行业背景资料
  另行统计，不能补足该用户证据来源门槛。
- 有效用户证据可以由完整讨论证据和范围有限证据共同组成，但必须分别计数并
  披露。大量范围有限证据可以交叉支持重复的个人经历，不能因此升级为对某一
  未完整读取讨论的“社区共识”判断。
- 需求证据池至少 50 条合格用户原话，才能跨过最低用户群体研究门槛；目标产品
  评论、竞品评论、官网和背景资料不得补足这 50 条。研究涉及 3 个及以上核心
  用户群体、多个国家/语言市场，或网站覆盖多个实质不同任务时，默认最低研究
  目标提高到 100 条需求用户原话。合格原话不设固定上限。
- 至少 4 类独立渠道；单个平台原则上不超过全部证据的 50%。满足数量门槛不
  等于完成渠道发现，不能用固定的熟悉平台组合替代动态平台地图和遗漏检查。
- 同一用户通常最多计入 3 条原话。
- 每个核心群体至少需要 10 条原话、5 名独立用户和 2 类渠道。
- 同时收集支持、负面、放弃、替代方案和付费决策证据。

计数前执行去重与降权：

- 为每位用户分配稳定的内部 U 编号。每个 OPP 的独立用户数按去重后的 U
  计算，不得因关联多个 S、Q、G 或 SOL 而重复计数。
- 同一平台按公开账号或其他可验证身份合并；跨平台仅在用户明确自我关联
  账号或身份时合并。同一用户重复讲述同一经历，只计一名用户和一个行为
  信号。
- 跨平台身份无法判断时，披露潜在重复，不假装已经确认；将可能重复的
  记录归为潜在重复组，并以每组一名用户计算保守下限。
- 同一内容的转载、镜像、引用和聚合只计一个来源；聚合页应追溯原始页面。
- 同一营销活动生成的多篇推广内容视为同一推广簇，不得冒充独立验证。
- 推广、赞助、联盟和疑似软文降为 C 级或排除；披露真实使用且语境可核验
  的部分可单独记录，但不得仅凭推广评价归纳优缺点。

公开证据不足时报告实际数量，不得降低质量标准凑数。相关结论相应降为中或低置信度。

## 11. 证据饱和

达到适用的需求证据数量下限后继续执行扩展轮次：窄范围研究至少 50 条；涉及
3 个及以上核心群体、多个国家/语言市场或多个实质任务时至少 100 条。每轮记录
是否找到新的合格用户原话、新平台或
新社区，以及是否出现新的核心群体、任务、触发事件、问题、替代方案、付费
因素或反证。

- 连续三轮既没有新的合格用户原话、新平台或新社区，也没有新的重要主题、
  方案或反证时，才能
  表述为“在已覆盖的公开证据范围内达到饱和并停止”，不得暗示完整市场已经
  绝对饱和。
- 尚未饱和且仍有合法公开线索可追时继续研究，不设合格原话数量上限。
- 只有达到上述公开范围饱和，或触发 `research-playbook.md` 的网站不可访问、
  平台受限、无联网能力等失败处理边界，才停止继续收集；停止时披露尚未覆盖
  的市场、语言、渠道、群体和方案方向。

## 12. 内部研究账本的关键结论格式

以下格式只用于内部研究账本的审计与推理，不是外部报告中的第二套证据块。
外部三段式报告使用第 16 节规定的总清单、故事穿插证据和逐题证据格式，内部
推理字段不对外展示。

```text
结论：
适用用户群体：
用户原话与来源：
已确认事实：
推理过程：
反面证据：
置信度：高 / 中 / 低
仍然未知：
```

不要使用没有统计基础的精确百分比。根据证据直接性、独立来源、背景清晰度、跨平台一致性、时间有效性和反证强度判断置信度。

## 13. 抽样偏差

登记每类平台容易覆盖和遗漏的人群。评价渠道可能集中极端体验，讨论社区可能
偏向特定职业或技术水平，应用或扩展商店偏向相应终端用户，产品社区主要覆盖
现有用户，短内容社交渠道可能受到推广和算法推荐影响。不得让预先熟悉的平台名
代替对实际用户聚集地的发现。

公开评论不是代表性人口样本。不得从评论数量推断市场规模、用户占比或观点在全部用户中的真实比例。

## 14. 身份、隐私与推理边界

- 描述单一真实用户时，只使用该用户公开自述或能够直接验证的身份线索。
- 不根据姓名、头像、语言风格或刻板印象推断敏感属性。
- 区分相关性与因果关系；无法证明因果时明确说明。
- 无法确认用户真实性、产品使用、付费状态、日期或版本时写未知。
- 不把综合人物的身份、经历或敏感属性归给任何一位真实个人，也不提供足以
  反向识别真实个人的拼接细节。
- 内部研究账本可为去重保留必要的公开账号线索；外部报告默认不展示账号名、
  姓名、精确雇主、精确地点或罕见属性组合。直接链接仍需保留，但正文不得
  额外拼接可识别信息，也不得把不同来源的身份线索组合成真实个人档案。
- 敏感或脆弱人群只聚合呈现。不能充分去识别的材料不得进入代表人物故事；
  即使来源公开，也不能用戏剧化叙事提高其被反向识别的风险。

## 15. 证据驱动的虚构代表人物

可以创作**证据驱动的虚构代表人物**，把多位公开用户的原话、语气、用词、
任务和行为综合成可读的第三人称贴身视角故事。可以在证据允许的范围内推理并
创作人物的身份背景、国家或文化处境、场景、情绪、利益、损失、决策、因果、
结果和叙事顺序。报告必须在人物首次出现处明确说明：这是多位公开用户经历的
综合创作，不是单一真实用户、真实采访或逐字访谈，不得让读者误以为研究者
采访过该人物。

先按角色、国家/文化、工作流、利益、决策权、付款关系和需求阶段识别实质不同
的用户群体。发现几个达到核心群体证据门槛的群体，就必须分别创作几个独立
故事；不得用一个平均人物覆盖角色、付款关系、组织规模、国家制度或决策路径
实质不同的群体。证据受限的群体单独说明缺口，不并入证据充分群体。

每个核心群体故事通常不少于 1500 个中文字，且必须采用第三人称贴身视角，
让叙述紧跟人物当下看到、想到、担心和权衡的内容，但不得写成用户亲口自述。
故事以连续场景自然覆盖：人物背景与文化处境、日常生活/工作、原任务、触发事件、具体失败、情绪变化、关系
与利益、当前变通、时间/金钱/风险/机会代价、搜索和比较、信任建立、使用者/
决策者/付款者、付费临界点、理想结果和仍未知。字数只是防止过度压缩，不能为
凑长度添加无证据的关键事实；证据不足时宁可明确降级，也不能写空泛长故事。

故事第一段必须先让外行人明白人物是谁、平时做什么、要对什么结果或关系负责，
并在完成读者定位后呈现一个具体且有压力的生活或工作时刻。通过动作、受阻、
反复尝试、时间流逝和选择冲突让情绪自然显现，不得为了制造悬念而隐藏身份、
任务或责任，也不得只给人物贴“焦虑”“痛苦”“愤怒”等标签。写出人物原本想
完成什么，哪里第一次失控，哪次自救再次失败，代价怎样
逐步逼近成绩、收入、信誉、关系、身体、机会或时间自主。需要呈现人物在关键
时刻可能怎样理解局面、害怕失去什么、为什么既渴望产品又不敢相信它；这些内心
活动始终属于证据约束下的综合推理，不得加引号冒充原话。

故事必须继续追问“用户真正想保护或获得什么”：表面需求可能是转写、摘要、
自动化、搜索或节省步骤，底层需求可能涉及掌控感、确定性、可信结果、身份表现、
时间自主、风险降低、关系责任、收入或机会。只有多条相容证据中的语言、行为、
损失和决策能够共同支持时，才可命名某个底层需求；否则写未知。故事要写出用户
在关键时刻可能怎样想，但这些内心活动必须明确属于综合推理或故事化表达，不能
加引号、不能冒充真实用户亲口说过。

只能综合任务、角色、市场、时间和产品状态相容的用户证据。不同群体、不同
产品阶段或互相矛盾的经历不得拼成单一因果链；它们应拆成不同代表情境，并
把差异作为反证或边界呈现。每个材料性细节都必须能追踪到一个相容证据组，
并在内部账本说明它属于直接事实、综合推理还是故事化创作。内部账本保留该
证据组的编号映射；外部故事不展示映射说明或逐字原话，只在第二问回答下列出
全部相关来源链接和逐链接调研总结。

每一个重要的身份、国家或文化背景、情绪、利益、损失、决策、因果和结果判断，
都必须在内部逐项写明：由哪句原话直接支持、由哪些相容原话共同推理，或只是
怎样的故事化衔接。不得让一条宽泛原话替整段人物设定兜底；找不到映射时删除
该判断，或明确写成未知。外部不展示这份内部解释或用户原话，但第一部分必须
完整登记参与这些理解的全部来源；第二部分故事中的关键理解还要就近穿插对应
链接、完整调研总结和研究观点/局限，不能只选最戏剧化或点赞最高的少数来源。

情绪不要求用户直接说出“我焦虑”“我愤怒”等标签。强烈措辞、反问、重复
求助可以提供语气证据；退款、取消、迁移、改回手工、降级或放弃等行为只能
作为情绪线索，不能单独证明任何具体情绪。命名具体情绪时，原话中的语气或
措辞必须与行为信号或另一条独立语境信号相互印证。即使证据充分，情绪也始终
写成推理，并用“可能”“更像是”“综合来看”等与证据强度匹配的措辞；禁止
推断临床诊断或其他敏感心理状态。

每个故事都必须区分以下四层，不得把后三层写成用户亲口确认：

- **直接事实**：公开原话或可核验来源明确陈述的身份、事件、行为或结果。
- **综合推理**：由多位用户的一致语气、措辞、行为和结果推导出的解释。
- **故事化细节（叙事性细节）**：为连贯、可读而安排的视角、顺序、转场、
  概括性背景或场景描写；它不是新增证据。
- **未知**：现有公开材料不能确认的真实身份、动机、因果、金额、结果或
  其他信息。

允许创作故事化细节，但它不得与任何支持证据或反证冲突，也不得填平关键
未知。不得编造精确金额、比例、发生率、市场规模、产品效果，或把敏感属性
归给真实个人；精确值只有在直接引文或可核验来源明确提供时才能作为该来源的
事实引用，不能外推。证据越弱，身份、情绪、因果和结果的表达越保守；
反证必须限制故事强度，必要时拆分为不同代表情境，不能为了戏剧性省略反例。

## 16. 外部三段式交付与证据展示

外部固定输出三个一级部分，顺序为：完整证据总清单 → 全部不同用户群体的
沉浸故事 → 固定 14 问。外部不展示用户逐字原话；用户证据统一改为“直接链接
+ 完整调研总结 + 研究观点/局限”。产品网站证据以营销策略分析为核心，逐产品
展示网页 Title、Meta Description 和首页 H1。

### 第一部分：完整证据总清单

总清单必须位于故事和问答之前，将本次实际取得、核验并用于研究的来源按证据
范围全部列出：

1. 完整讨论证据。
2. 范围有限的真实用户证据。
3. 目标产品真实用户证据。
4. 其他解决方案与竞品真实用户证据。
5. 目标产品及全部已发现解决方案的官网、功能、用例、定价、案例、文档、政策
   和其他营销链路页面。
6. 用于解释平台规则、行业背景、版本和市场环境的官方或间接来源。
7. 搜索摘要、截断内容、第三方转述、访问受限、疑似推广、低信息或无法核验的
   受限线索，
   但影响研究范围判断的重要线索。

同一 URL 在总清单中只出现一次，并注明它支持的用户群体、产品和问题主题。
所有实际参与故事、问答、产品判断或机会判断的来源必须出现，不能只列高赞、
戏剧化、支持结论或方便解释的来源。第 7 类必须明确写“受限线索，未作为正式
结论证据”，并说明它实际被用于发现了什么。

每个用户来源采用：

```text
[能说明讨论主题的自然标题](可点击的原始直链)
证据范围：完整讨论证据 / 范围有限证据。
实际读取边界：整场讨论及排序；或完整主帖/独立评论、必要父级和直接回复。
平台、日期与点赞：平台；公开日期；平台显示的点赞数/净赞/综合分数，或“隐藏”。
完整调研总结：用大白话说明谁在什么处境下讨论什么、发生了什么、主要观点、
痛点、利益、情绪、行为、替代做法、决策和结果。只有完整讨论证据才总结评论区
主要认同和分歧；范围有限证据只总结实际读到的直接上下文。
研究观点与局限：说明研究者从该材料理解到了什么、它支持或反驳什么、证据资格
和局限是什么，以及明确不能外推什么。不得写成假引语，不得添加页面中不存在的事实。
关联位置：用户群体；目标/竞品；相关问答主题。
```

每个产品或背景页面采用：

```text
[页面自然标题](可点击的原始直链)
页面类型：官网首页/功能/用例/案例/定价/文档/政策/官方规则/背景资料。
页面总结：这个页面明确展示或规定了什么。
研究观点与局限：它如何支持产品定位、细分用户、营销链路、功能覆盖或背景判断；
同时说明产品方陈述不能证明真实效果，间接资料不能替代用户证据。
关联位置：产品；相关问答主题。
```

### 第二部分：全部不同用户群体的沉浸故事

发现几个达到门槛且在角色、国家/文化、任务、利益、决策权、付款关系或需求阶段
上实质不同的群体，就写几个独立故事，不能只写最显眼的一种。每篇通常不少于
1500 个中文字，采用第三人称贴身视角，遵循第 15 节全部证据和虚构边界。

故事不是人物介绍，而是一段能够让外行人进入用户生活与思维的连续经历：日常状态
→ 任务和责任 → 触发事件 → 具体失败 → 当时可能怎样想 → 情绪如何累积 → 利益和
关系怎样受损 → 怎样自救和绕路 → 付出哪些时间、金钱、风险、心理和机会代价 →
怎样搜索、比较、建立或失去信任 → 谁使用/决定/付款 → 什么结果足以付费 → 理想
结果 → 仍未知。必须把表面功能需求追到有证据支撑的底层需求和问题本质。

在每个关键转折或重要理解后，用一句自然、可独立理解的研究性总结承接可点击
来源直链，再补充必要的研究观点或局限。多条来源支持同一理解时，允许在同一次
自然解释中合并呈现，并分别交代它们共同支持什么、各自边界是什么；不得为了
逐个展示链接而让故事变成来源巡游。证据句必须解释刚刚发生的场景、情绪、
利益或决策，读起来应像故事推演的一部分，而不是突然插入证据卡片；不展示用户
原话，不把来源只堆在故事末尾。第二部分使用的每个来源都
必须已经出现在第一部分总清单中，但可以为方便理解再次出现。

### 第三部分：固定 14 问

每个问题先用大白话给出已经消化的回答。第 2 问概括本次识别出的全部用户群体并
指向第二部分的完整故事，不机械复制全部故事；第 3 至第 8 问仍按各群体分别回答。
每题回答后列出与该题相关的全部证据直链、完整调研总结和研究观点/局限，不得用
“已在总清单列出”省略。用户来源不展示逐字原话。

### 全量用户来源链接与逐链接调研总结

第一部分开头分别声明完整讨论证据数、范围有限证据数、受限线索数，并继续分解：
有效支持来源、反证来源、低信息或疑似推广来源、独立用户保守数、用户群体数、
渠道类型数，以及能够读取公开点赞数据的来源数。数字只写实际结果。正式用户
证据总数只包含前两类，不包含受限线索。

每个问题注明“本题关联 X 个用户来源，以下全部列出”。每个链接使用以下格式：

```text
[帖子、讨论或评论的自然标题](可点击的原始直链)
证据范围：完整讨论证据 / 范围有限证据。
实际读取边界：如实说明读到了整场讨论，还是一篇完整主帖/评论及必要上下文。
平台、日期与点赞：平台；公开日期；平台显示的点赞数/净赞/综合分数，或“隐藏”。
完整调研总结：用大白话如实说明这条材料的用户身份与处境、发生的事情、主要观点、
痛点、利益、情绪、行为、替代做法、决策和结果；只有完整讨论证据才概括整个
评论区的赞同与反对意见。
研究观点与局限：说明这条材料支持了什么理解、带来了什么新线索、存在哪些局限，
以及范围有限证据不能承担的社区或群体结论。
不得编造页面没有的信息，也不得把总结写成用户逐字引语。
```

证据来源总清单中的每个正式用户证据必须至少在一个相关故事或问题下出现。某一问题
内部列出所有相关来源并去重，按公开点赞从高到低排列；无公开点赞的来源放在
有数据来源之后。最高赞相关来源、高赞反对意见、反证、低信息和疑似推广来源
都不得因为不符合主结论而隐藏，但总结必须如实说明其资格与局限。

同一来源可以在多个问题下重复链接和相应角度的总结。整份报告结束前，内部执行
数量对账：报告声称使用 N 个正式用户证据，则完整讨论证据与范围有限证据的去重
链接合计必须恰好为 N 个；不能声称调查很多却只展示几条，也不能用同一讨论的
多个评论机械虚增 N。受限线索另外计数，不得混入 N。

### 逐产品营销链路、细分用户与痛点覆盖证据

内部必须完整阅读每个产品公开可访问的首页、功能、角色/用例、案例、定价、
对比、文档、帮助和政策页面，并顺着公开营销链路观察从发现到转化的设计：
搜索入口的 Title/Meta → 首页首屏与 H1 → 角色或用例承接 → 功能解释 → 案例、
评价和社会证明 → 安全、风险与异议处理 → 定价与套餐 → CTA → 公开可访问的
试用、注册或演示入口。受登录限制的后续流程不绕过，只记录公开边界。

研究重点是理解每一步想吸引谁、让他相信什么、消除什么疑虑、产生什么情绪，
以及采取什么下一步；据此判断产品在供给生态中的位置、主要差异化叫卖点、核心
结果和转化策略。功能分析服务于理解“怎样解决用户痛点”和“怎样卖出去”，不能
退化成功能清单。

从称呼、角色/用例页、案例、行业词、组织规模、定价单位、套餐分层、CTA 和
销售方式反推的目标用户，只能标为“产品页面反推的细分用户假设”。内部记录它
可能对应的角色、行业、规模、地区/语言、成熟度、任务触发、使用者、决策者、
付款者和预算方式，并返回需求证据池继续验证。只有真实用户证据相符时，才能把
它升级为实际用户群体佐证；产品页面本身不能证明真实用户构成。

```text
网页 Title 原文："网页 title 元素原文；未设置或未能读取时如实写明。"
网页 Title 中文："忠实中文翻译。"
Meta Description 原文："页面描述原文；未设置或未能读取时如实写明。"
Meta Description 中文："忠实中文翻译。"
首页 H1 原文："首页主标题原文；未设置或未能读取时如实写明。"
首页 H1 中文："忠实中文翻译。"
显眼营销文案："必要时补充首屏副标题、主要 CTA 或高频核心卖点原文。"
显眼营销文案中文："忠实中文翻译。"
细分用户/用例页文案："最能表明产品主打人群和场景的原文。"
细分用户/用例页文案中文："忠实中文翻译。"
定价或转化节点文案："最能表明付费对象、价值单位或下一步动作的原文。"
定价或转化节点文案中文："忠实中文翻译。"
直接来源：[产品官网原始页面](可点击的直接 URL)
```

逐产品先用大白话回答：它在供给生态中主攻哪一段、页面反推它主打哪类细分用户、
与其他方案怎样区分、主要卖什么结果、怎样通过营销链路建立信任并推动付费。
然后将已验证用户痛点逐项映射到产品功能和承诺，标记为直接覆盖、部分覆盖、
间接缓解、公开页面未覆盖、产生新代价或未知；再用真实用户证据验证实际效果。
每个产品必须分别得出“值得学习的做法”和“做得不足或可能切入的地方”。

“营销设计做得好”可以根据页面层级、信息一致性、细分承接、信任设计和 CTA
链路判断；“产品实际解决得好”只能由真实使用证据支持。官网没有提到某项痛点，
只能说明公开页面未覆盖或未强调，不能证明后台功能绝对不存在。用户抱怨也不能
单独证明所有版本或所有用户都失败，必须记录时间、版本、市场和反证。

Title、Meta Description 和首页 H1 三项必须分别核验并提供中英文；关键链路
文案只保留足以支撑细分用户、差异化和转化判断的内容。不得把产品方宣传写成
已验证效果，也不得因为产品数量多而只深挖少数产品。

证据展示不得包含内部编号、等级、门槛代码、去重键、置信度或内部推理账本。
逐链接调研总结可以解释帖子发生了什么和主要分歧，但不额外虚构动机。没有合格
用户证据时明确写“未找到符合完整讨论或范围有限证据标准的公开用户来源”；产品没有可核验官网时写“未找到
可核验的 Title、Meta Description 或 H1”，不得用搜索摘要或第三方转述代替。
